## 1. 通用配置、格式与认证

通知配置位置为 `push.screenshot.image_host`，值必须为图床映射列表；每项使用 `provider`、可选 `token`、可选顶层 `expiration`、可选 `options` 映射。CLI 则使用 `--upload` 内联 YAML 映射，多项以顶层分号分隔，不读取 YAML 文件。

- `provider` 会去掉首尾空白并转小写。`token` 是直接字符串或完整 `${ENV_NAME}` 引用，环境变量名只接受 ASCII 字母、数字和下划线且不能数字开头；不递归展开、不修剪直接凭证。数字形凭证必须加引号。
- 不要把 `Bearer ` 前缀写进 token，适配器会自行添加认证头。Superbed、Catbox、BeeIMG.com 则使用各自的认证位置，见下表。
- `options.permission` 缺省为整数 `1`；整数选项不接受布尔值。权限参数表达上传意图，不等于直链访问控制，更不能把“未公开列出”当成严格私有。
- 六个适配器的 MIME 映射均支持 `.png`、`.jpg` / `.jpeg`、`.webp`；它们上传已有内存字节，不负责转码。未知后缀拒绝，服务端是否接受该格式仍由站点策略决定。部分旧函数说明中的“内存 PNG”不是当前实现的唯一格式限制。
- 通知固定截图为 JPEG，上传名为输出变量名加 `.jpg`；CLI 默认 JPEG，显式 `--output` 文件后缀决定 PNG / JPEG / WebP / raw，目录输出仍默认 JPEG。`raw` 与上传同时使用会在截图前拒绝。
- 所有成功候选链接都经过 HTTP(S) URL 语法校验，拒绝用户信息、控制字符和非法主机等；不要求图片扩展名，不发送 HEAD / GET 探测，不保证链接持续可访问。

源码：[注册表](../modules/image_host/registry.py#L29-L33)、[凭证与链接校验](../modules/image_host/core.py#L115-L194)、[MIME 映射](../modules/image_host/providers.py#L39-L48)、[CLI 格式选择](../modules/screenshot/cli.py#L308-L362)、[通知上传](../modules/screenshot/pipeline.py#L69-L106)。

### 限定标量与 PowerShell 转义

配置文件仅在 `push.screenshot.targets[].target` 和 `push.screenshot.image_host[].token` 接受成对反引号字面标量；CLI 内联上传只在各图床项顶层 `token` 接受，不扩展到 `options`、provider 或任意嵌套键。反引号不是通用 YAML 引号，也不是命令执行语法；不闭合、跨行或闭合后紧接非终止字符均拒绝。正常 YAML 引号、重复键与 merge 规则仍生效，写回使用合法 YAML 字符串，不保留反引号外壳。

完整 `${ENV_NAME}` 引用在上传时解析一次，不递归展开；反引号不使环境引用变成禁止解析的字符串。PowerShell 外层使用单引号，保留美元符号、双引号与反引号，例如：

```powershell
python .\2RPM.py screenshot --source 'AppName@{version}' --upload 'provider: catbox, token: `${CATBOX_TOKEN}`'
```

PowerShell 双引号字符串会展开变量，反引号还会参与 shell 转义；不要把 shell 处理后的文本误认为程序原始输入。单引号参数中的字面单引号需写成两个连续单引号；这里的反引号不作 PowerShell 转义。

### 窗口版本匹配边界

仅 `@{version}`、`@{VERSION}`、`@{Version}` 三种标记合法，必须位于非空应用名末尾且只出现一次。无标记按完整标题精确、区分大小写匹配；有标记时应用名不区分大小写，纯应用名也能匹配。带后缀时应用名与后缀必须由 ASCII 空格分隔，不接受控制字符；ADB 不支持该标记。多个匹配时拒绝截图。

数字版本为 2～4 段 ASCII 数字，段数限制不是每段位数限制；可带 `v` / `V` 或大小写不敏感的 `version ` 前缀。版本后允许以空格、`+` 或 `-` 引出的自由尾部，所以 `AppName 1.2 Launcher`、`AppName 1.2 Settings` 合法；`AppName 1.2.3.4.5` 不合法，但 `AppName 1.2 +build.3.4.5` 合法，尾部内容不再按版本段计数。

哈希为 7～64 个十六进制字符，可带一个 `g` / `G` 前缀（不计入长度）；哈希不接受自由尾部，也不接受 `v` / `version` 前缀。6 位、65 位以及 `gabc1234 Launcher` 均不匹配。

源码：[限定标量](../modules/yaml_scalar_compat.py)、[标题匹配](../modules/screenshot/title_match.py)。

## 2. 六图床接口与参数

所有上传均使用 multipart 表单，只上传单个内存文件，不提供批量、远程 URL 抓取、Base64、目录或模板能力，也不下载图片验证；表中的“返回值”指项目实际读取的成功字段，而不是服务的全部响应内容。未知 options 通常告警后忽略，并不等于参数已生效；明确禁止项则直接失败。

| provider | 固定上传端点 | 认证与文件字段 | 项目认可的 options | 返回值 |
| --- | --- | --- | --- | --- |
| `catbox` | `https://catbox.moe/user/api.php` | 非空 token → 表单 `userhash`；`reqtype=fileupload`；文件 `fileToUpload` | `permission: 1`；`album_id`、`strategy_id` 明确告警忽略，其余未知项也忽略 | 2xx 响应纯文本 URL |
| `wmimg` | `https://wmimg.com/api/v1/upload` | 账号 token → `Authorization: Bearer …`；`Accept: application/json`；文件 `file` | `permission: 0/1`、整数 `album_id`、整数 `strategy_id` | 2xx 且 `status` 严格为 `true`，读取 `data.links.url` |
| `beeimg` | `https://beeimg.com/api/upload/file/json/` | 非空 token → 表单 `apikey`；文件 `file` | 仅 `permission: 1`，转为 `privacy=public`；`albumid` 为长度 5 或 9 的字符串且必须有凭证；显式 `privacy` 拒绝 | 2xx 且 `files.status == "Success"`，读取 `files.url` |
| `beeimg_cn` | `https://www.beeimg.cn/api/v2/upload` | 非空 token → Bearer；文件 `file` | `permission: 0/1` → 字符串 `is_public="0"/"1"`；整数 `album_id`；由编排选择的正整数 `storage_id`；显式 `is_public` 拒绝 | 2xx 且 `status == "success"`，读取 `data.public_url` |
| `boltp` | `https://www.boltp.com/api/v2/upload` | 非空 token → Bearer；文件 `file` | 同 v2 权限、相册规则；手填 `storage_id` 必须是非布尔非负整数，允许 `0` | 同 BeeIMG.cn |
| `superbed` | 默认 `https://api.superbed.cc/api/v1/upload/`；备用同路径 `.cn` 域名 | 非空 token 必填；v1 使用 `X-API-Key`，文件 `files` | `api_version: v1`（默认）或 `legacy`；仅 `permission: 1`；v1 可用 UUID 字符串 `folder_id` | v1 要求 `success: true`、整数 `total=1`、`succeed=1`、`failed=0`，唯一 `files[0].url` 有效 |

### Catbox

允许无 token 尝试匿名上传；有 token 时用作 `userhash`，不是 Bearer。没有项目接入的相册、存储驱动或保存期限；不能从“没有传期限”推断永久保存。`permission: 0` 会失败，不提供严格私有上传。

源码：[upload_catbox](../modules/image_host/providers.py#L51-L90)。

### WMIMG（无铭）

**没有 `storage_id` 参数。** 存储选择参数是 `strategy_id`，不查询 v2 存储组、不使用存储元数据缓存、不进行驱动恢复；误填 `storage_id` 只会作为未知项忽略。`album_id` 和 `strategy_id` 只校验非布尔整数，编号是否存在由服务端判断。

账号 token 直接用于 Bearer 上传，无需先创建临时 token。原生 API 的表单 `token` 是另一种临时上传令牌，当前适配器没有接入，不应与顶层账号 `token` 混用。**顶层 `expiration` 已接入**，编排会换算成表单 `expired_at`。

本地记录：2026-10-04 账号 Bearer 上传成功；匿名请求读取超时，不能据此断言服务不支持游客上传，也不能排除图片已保存。2026-10-13 的单次五分钟期限样本上传成功，响应未回显期限，之后手动确认图片删除且直链 404；这是历史样本，不是本次验证，也不保证其他账号的时区或精确删除时间。

源码：[upload_wmimg](../modules/image_host/providers.py#L93-L158)、[WMIMG 期限注入](../modules/image_host/registry.py#L217-L225)；本地资料：[wmimg_api.md](API/wmimg_api.md#L11-L25)。

### BeeIMG.com

匿名上传可省略 token；指定 `albumid` 时必须认证，长度 5 表示相册、长度 9 表示文件夹，保持字符串，不能写成整数。项目只发送 `privacy=public`。源码记录的 `private` 只是非公开列出、持链仍可访问；`truly-private` 依赖 Premium，其降级和无权限行为未完整确认，因此当前拒绝原生 `privacy` 和严格私有请求。没有项目接入的 `storage_id` 或保存期限。

源码：[upload_beeimg](../modules/image_host/providers.py#L161-L216)。

### BeeIMG.cn

合法手填（内置正整数且大于 0，布尔值不合法）时**手填优先**：首次上传直接使用手填存储，零 `GET /api/v2/group`、零 `GET /api/v2/user/profile`，也不读写存储缓存。无手填或手填非法时只查询一次 `GET /api/v2/group` 并**自动选择组内首项**；组列表须包含正整数编号，按返回顺序去重，空列表失败。当前适配器不查询账号资料接口，不以资料权限决定是否上传。

**首次手填不按组上限预裁剪**：手填存储时不会先按组 `file_expire_seconds` 裁剪期限，期限按第 4 节规则计算；期限 `0` 不保证永久，`None` / `0` 只表示不做本地裁剪，不代表服务端永久保留。

手填失效会得到精确存储拒绝，此时刷新一次存储元数据并排除刚被拒绝的编号后重传一次，**精确拒绝仅恢复一次**。手填成功本身不读写存储缓存；无手填时的组查询结果按凭证在事件内复用，并可使用磁盘缓存，24 小时内命中可零 `group` 查询。选择失败只属于当前槽位，不污染共享查询结果。

底层适配器仍要求调用方自行提供正整数 `storage_id`；历史错误码 `profile_forbidden` 与 `profile_forbidden_invalid_storage` 仅为兼容展示保留，不再代表当前仍需资料权限，也不再依赖 `profile_state=forbidden`。

源码记录的 2026-09-30 样本中，`is_public="1"` 上传成功、直链可匿名访问，但服务返回 `data.is_public=false`，说明账号策略可能不采纳公开意图；`permission: 0` 同样不能作为已实现私有访问控制的保证。

源码：[v2 适配器](../modules/image_host/providers.py#L368-L458)、[查询与选择](../modules/image_host/storage.py#L125-L165)。

### Boltp

当前注册表**不依赖组内存储列表或账号默认存储**。候选为“有效手填值（若有）→ 2 → 3”，保序去重；自动最多两个编号，总候选最多三个。`2/3` 是项目兼容策略，不是动态发现或服务可用性保证。

未配置 `expiration` 时不查询组或账号资料，也不读写持久存储缓存；配置期限时只查询 `GET /api/v2/group` 的 `file_expire_seconds`，同一通知事件按凭证复用成功或失败结果。查询失败则该项失败，不无条件上传。上传候选切换不会重新启动期限倒计时。

源码仍保留通用查询函数对 Boltp profile HTTP 403 的兼容，但当前注册表的 Boltp 上传路径不调用该资料接口。2026-10-03 记忆中的“BeeIMG.cn 与 Boltp 均自动发现存储、24 小时缓存”是历史实现，不能直接用于描述今天的 Boltp 行为。

源码：[Boltp 候选与期限](../modules/image_host/registry.py#L92-L132)、[只查组期限](../modules/image_host/storage.py#L99-L122)、[事件内期限复用](../modules/image_host/context.py#L302-L316)、[底层适配器](../modules/image_host/providers.py#L461-L476)。

### Superbed（聚合图床）

默认及显式 `api_version: v1` 使用 `/api/v1/upload/`、`X-API-Key`、文件字段 `files`，可传 UUID 字符串 `folder_id`，禁止 `categories`。显式 `api_version: legacy` 使用 `/upload`、表单 `token`、文件字段 `file`，可传字符串 `categories`（允许空字符串），禁止 `folder_id`。版本只接受这两个精确小写值。

两版本均先 `.cc`，失败后最多尝试 `.cn` 一次；不会跨版本回退，也不会混用认证方式。legacy 要求整数 `err == 0` 并读取根级 `url`。v1/legacy 均检查明确的失败标记和 URL；参数/凭证预校验失败时不请求任何域名。`privacy` 与 `permission: 0` 被拒绝，公开权限只是项目约定，不作为服务端隐私保证。没有项目接入的保存期限或 `storage_id`。

版本迁移：省略版本的配置现按 v1 处理。已有 `categories` 的配置必须显式补 `api_version: legacy`，或主动迁移为真实文件夹 UUID；程序不自动转换路径或改写配置。

源码：[上传与域名切换](../modules/image_host/providers.py#L219-L281)、[响应及版本参数](../modules/image_host/providers.py#L284-L365)。

## 3. 匿名入口限制不等于服务事实

| provider | CLI 是否允许省略 token | 通知/注册表收到空凭证时 | 服务事实边界 |
| --- | --- | --- | --- |
| `catbox` | 是 | 不发 userhash，尝试匿名 | 源码记载文档契约，未以本次真实上传验证 |
| `beeimg` | 是，但带 `albumid` 不允许 | 不发 apikey；带 albumid 则失败 | 不能把匿名入口开放理解为服务永远接受 |
| `wmimg` | 否 | 省略 Authorization，允许尝试游客上传 | 本地文档描述游客上传；历史匿名超时，成功未确认 |
| `beeimg_cn` | 否 | 省略 Authorization；匿名 group 查询后尝试上传 | 底层契约允许空令牌，不代表当前匿名策略已验证 |
| `boltp` | 否 | 省略 Authorization；依当前候选策略尝试 | 同上；固定编号不是匿名可用性保证 |
| `superbed` | 否 | 本地拒绝空凭证，不发上传请求 | 当前集成要求凭证，不推导服务全部能力 |

CLI 显式 token 必须是非空字符串；WMIMG / BeeIMG.cn / Boltp / Superbed 缺少 token 属于截图前参数错误。完整环境引用在静态解析时可以通过，但运行时变量缺失或为空：Catbox 和不带 `albumid` 的 BeeIMG.com 可降级匿名，其他项失败后继续处理下一项。

通知不同：缺省 token、`null`、空字符串会解析为匿名空凭证，由适配器决定；但显式 `${ENV_NAME}` 缺失或为空时，该项失败并进入下一图床，**不会**自动降级匿名。不要用 CLI 的 token 必填限制描述服务端不支持匿名。

源码：[CLI 静态解析与凭证准备](../modules/screenshot/inline_upload.py#L169-L228)、[核心凭证解析](../modules/image_host/core.py#L115-L133)。

## 4. 保存期限与缓存

### 顶层 expiration

仅 `wmimg`、`beeimg_cn`、`boltp` 接入期限；其他三个 provider 遇到合法期限会记录“该图床不支持保存期限，已忽略”，仍按站点默认策略上传。这里的“不支持”仅指项目适配，不推断服务原生能力。

- 使用字符串，如 `7d`、`1d12h`、`5m`、`1w2d3h4m5s`；单位按 `w d h m s` 降序且不能重复，每段必须为正整数，大小写敏感，不允许内部空格、小数或负数。`1h30m` 合法，`0s`、`1h0m`、`30m1h` 不合法；允许前导零和 `90m` 这类未归一化值。
- 参数省略表示不主动发送期限，沿用服务策略；不是永久保存。即使 provider 不支持期限，非法期限也会使该项失败，而不是直接忽略。
- `expiration` 必须在图床项顶层。普通 `options.expired_at` 不会作为原生期限透传；与顶层 expiration 同时存在会报配置错误，单独填写则是未知选项、告警忽略。`options.expiration` 也不是期限入口。
- 注册表为每条图片上传链固定起点，以经过秒数计算截止时间，向下取整后转换为本机本地时间 `yyyy-MM-dd HH:mm:ss`。发送前必须仍在未来，过期或不可表示则失败。
- BeeIMG.cn 根据组 `file_expire_seconds`，Boltp 根据专门查询的组期限裁剪；`None` / `0` 表示不做本地裁剪，不代表永久。恢复时与旧截止时间取更早值，绝不延长期限；缩短会记录告警。WMIMG 不查询组上限，仅转换请求期限。
- CLI 各图床项是独立单项上传链，各自计时；通知同一张图的故障转移链共享起点，前序耗时会消耗后续可用期限。期限不包含截图之前的时间。

源码：[期限语法与计算](../modules/image_host/expiration.py#L28-L132)、[期限编排](../modules/image_host/registry.py#L157-L249)、[固定图片起点](../modules/image_host/context.py#L323-L328)。

### 存储元数据缓存与图片保存不是同一件事

当前实际走持久存储元数据缓存的是 BeeIMG.cn。目录为 `%LOCALAPPDATA%\2RPM\image_host`，按站点和凭证的 HMAC 身份隔离，匿名独立；本机随机密钥文件为 `.storage-key`。缓存保存组内存储列表、组期限及查询时刻，BeeIMG.cn 的账号默认存储不作为选择依据，也不保存原始 token、图片或上传 URL；这不是对图片进行加密存储。

缓存从查询时刻起有效 24 小时，未来时间或到龄即视为失效。损坏、读取/写入/身份初始化失败会告警并降级，缓存写失败不让已经成功的查询或上传失败。同一通知事件复用元数据和失败快照，避免同代重复查询。Boltp 期限只在事件内复用，不使用此磁盘缓存；其余图床也不使用此缓存。

截图本地保留由 `push.screenshot.retention` 控制，与远端 `expiration` 独立；本地清理不等于远端删除。CLI 不执行自动保留清理，显式保存失败仍可继续上传。

源码：[缓存目录、身份、TTL](../modules/image_host/storage_cache.py#L91-L205)、[事件元数据复用](../modules/image_host/context.py#L260-L316)、[通知本地保存与上传](../modules/screenshot/pipeline.py#L88-L106)。

## 5. 故障转移与请求预算

以下以单图、单配置项为单位区分上传 POST 与元数据 GET；参数/凭证预校验失败可能为零请求。每次连接超时 5 秒、读取超时 15 秒，**不是每项 20 秒硬总时限**，也不是整个链的总预算。TLS 校验开启，不跟随重定向；超时不能排除服务端已保存，后续切换可能产生重复图片。

| provider | 上传 POST 上限 | 查询与切换条件 |
| --- | --- | --- |
| `catbox` / `wmimg` / `beeimg` | 各 1 次 | 不查存储、不在适配器内部自动重试；失败交给外层 |
| `superbed` | 2 次 | `.cc` 失败才用 `.cn`，覆盖 HTTP、传输、响应与 URL 校验等失败；不跨 API 版本 |
| `beeimg_cn` | 最多 2 次 | 手填优先直传；仅首次上传得到精确存储拒绝且纠错预算未用尽时，刷新元数据并排除被拒编号后重传一次 |
| `boltp` | 默认最多 2 次；额外不同手填值时最多 3 次 | 只有精确存储拒绝才继续下个去重候选；普通 HTTP/网络/业务错误立即停止该项 |

“精确存储拒绝”必须同时满足上传阶段、HTTP `200`、JSON `status == "error"`、`message == "不存在的储存驱动"`。相似文字、HTTP 403/429/5xx、超时、响应损坏、其他业务拒绝都不触发 v2 存储重传/枚举。

BeeIMG.cn 每张图每个配置位置只有一次纠错预算，**精确拒绝仅恢复一次**：手填失效并得到精确存储拒绝时，刷新一次存储元数据并排除被拒绝的编号后重传一次；预算已耗尽后再收到存储拒绝不再重传，但会失效相关缓存。组查询结果按凭证在事件内复用，正常缓存命中为零 `group` GET；无手填或手填非法时的一次组查询为 1 GET，恢复刷新再加 1 GET，因此最坏为 2 GET + 2 POST，而不是无限重试。期限 `0` 不保证永久。

BeeIMG.cn 的完整元数据查询只有 `GET /api/v2/group` 一次，不再由 group 与 `profile` 各一次 GET 组成，也不依赖资料权限决定是否上传。

Boltp 期限配置导致的 group 查询为每事件每凭证最多 1 GET（失败也复用），不配置期限则为 0 GET。候选枚举不走 BeeIMG.cn 的刷新恢复循环；手填 `2` 或 `3` 不会再重复尝试同编号。

通知每张图片都从列表首项开始，首个有效 URL 即停，前一张成功的图床不会变成全局首选。普通失败继续下项；共享图片输入或整个 hosts 配置错误直接结束。`attempts` 按配置项记录，不是 HTTP 次数。推送通道的 `push.retry` 重试复用已生成正文，不增加图床上传次数。

源码：[上传链与返回](../modules/image_host/registry.py#L157-L302)、[共用纠错预算](../modules/image_host/context.py#L352-L401)、[v2 精确分类与传输](../modules/image_host/v2_http.py#L40-L125)、[通知结果复用](../modules/notification.py#L501-L578)。

## 6. CLI 与通知行为对照

| 项目 | 截图 CLI | 自动通知 |
| --- | --- | --- |
| 输入 | `--upload` 内联文本，不读配置文件；不支持 `-c/--config`、`--image-host` | `push.screenshot.targets` 与 `image_host` |
| 上传策略 | 一次截图后串行上传全部声明项，前项成功也继续 | 每张图按顺序故障转移，成功即停；目标间独立 |
| 预校验 | 任一项内联语法、provider、凭证形态、期限等静态校验失败，整条命令截图前退出 2；重复 `--output` / `--upload` 拒绝 | 配置项错误通常在实际尝试时记录，继续后续图床；不做 CLI 式整链静态拒绝 |
| options 细节 | 并非全部在截图前校验；多数图床专属参数在适配器运行时校验 | 在存储编排/适配器实际尝试时校验 |
| 上下文 | 每图床项单独 context，不跨项共享事件元数据；仍可读持久缓存 | 每通知事件多个目标共用 context，各图片/位置有独立状态与预算 |
| 输出 | 阶段状态加各项最终结果；成功结果行保留 URL，失败使用固定分类；不输出服务原始响应 | 终端显示阶段状态；正文为 Markdown 图片或固定失败文字，固定告警追加正文，普通截图失败不阻断通知 |
| 诊断开关 | 当前 `_upload_all` 明确为 `diagnostics=False` | 同样关闭动态诊断 |
| 退出/结果 | 有上传时全部项成功才为 0，任一上传失败为 1；截图失败为 1，参数错误为 2 | 每目标每事件截图一次，多个推送通道复用，不为每个通道重新上传 |

CLI 带上传时退出码按上传结果决定：即使本地保存失败，只要全部上传成功仍可返回 0；没有上传时按保存结果返回。只有 `--upload` 不保存本地；裸 `--output` 保存到程序根目录的 `screenshot`，显式相对路径按当前工作目录解析。

终端状态包含“准备上传”“正在上传”、成功/失败和下一图床或备用域名切换。TTY 复用外层 spinner；非 TTY 输出无 ANSI 普通行，不另起动画。profile 权限失败使用固定中文提示，不回显 token、目标、缓存身份或响应原文。`diagnostics=False` 关闭动态服务诊断，不关闭安全阶段事件及文件记录；无状态回调也保留文件日志与 CLI 的权限失败提示。

阶段回调只负责显示；批次收尾只汇总既有事实，不新增网络、缓存读写或截图保存，不额外读取凭证。取消原样传播 `KeyboardInterrupt` / `SystemExit`，已完成终态不重写，未开始槽位记 skipped；请求计数只统计真正进入传输的请求，不把 started 回调阶段的取消当作已发请求。

源码：[CLI 参数入口](../modules/screenshot/cli.py#L212-L253)、[CLI 全部上传与结果](../modules/screenshot/cli.py#L284-L362)、[通知共享上下文](../modules/screenshot/pipeline.py#L109-L162)。

## 8. 旧监控 layout 迁移

旧监控 layout（`monitor.monitor_mode`、顶层 `wait/task/launch` 等）仅由 `load_config` 在加载配置文件时自动迁移；不代表任意旧推送字段也受支持。直接构造的运行时配置必须使用新 layout。当前模式的目标字段必须有效；`launch.type` 为 `program` 时填写 `path`，为 `task` 时填写 `task_name`。`task_scheduler.lookback_minutes` 为 `0` 时查询窗口至少为 1 毫秒，launch-task 查询固定回溯 1 分钟。
