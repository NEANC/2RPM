# 兼容性与实现细节

> 本文件面向维护者与从旧版本迁移的用户。日常使用请看 [README](../README.md)。
>
> 以下结论均来自当前源码，不把「保留在 YAML 中」视为运行时支持。

---

## 旧监控 layout 迁移

旧监控 layout（`monitor.monitor_mode`、顶层 `wait/task/launch` 等）仅由 `load_config` 在加载配置文件时自动迁移；不代表任意旧推送字段也受支持。直接构造的运行时配置必须使用新 layout。当前模式的目标字段必须有效；`launch.type` 为 `program` 时填写 `path`，为 `task` 时填写 `task_name`。`task_scheduler.lookback_minutes` 为 `0` 时查询窗口至少为 1 毫秒，launch-task 查询固定回溯 1 分钟。

## 无效项与兼容边界

以下写法不会被程序按用户预期处理，需要按右列的当前处理方式调整：

| 写法                                                                                         | 当前处理                                                                                                                     |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `push_settings`、`push_templates`、`push_channel` 以及 `process_end_notification` 等旧模板键 | 不是当前推送入口，不会自动迁移；默认结构之外的映射键可能在加载清理时删除。请改用 `push`、`templates`、`channels` 和 `on_*`。 |
| 截图子命令的 `-c/--config`、`--image-host`                                                   | 不支持，退出码 2；监控入口仍支持配置路径参数。                                                                               |
| 图床项 `options.expiration` 或单独的 `options.expired_at`                                    | 不是期限入口；两站适配器不会把用户填写的这两个选项作为期限发送。顶层 `expiration` 与 `options.expired_at` 同时存在直接冲突。 |
| `beeimg_cn/boltp` 的 `options.is_public`                                                     | 明确拒绝；使用整数 `permission: 0/1`，不接受布尔值，也不保证服务端权限策略采纳。                                             |
| `boltp` 的负数、布尔或字符串 `storage_id`                                                    | 上传阶段拒绝该图床项，不会像 BeeIMG.cn 一样自动替代。                                                                        |
| 任意额外图床 `options`                                                                       | 未知选项不等于生效；各适配器分别校验、忽略或告警，并非任意参数透传。Superbed 的版本互斥项见专节。                            |

## 图床存储与期限

### 存储选择

- `boltp` 不填 `options.storage_id` 时依次尝试 2、3；手填非布尔非负整数时先试手填值，再试去重后的 2、3（最多三个候选）。只有 HTTP 200、`status=error` 且 `message` 精确为“不存在的储存驱动”的存储拒绝才继续下一候选；其他失败转后续图床。不查询存储元数据，不使用磁盘存储缓存。
- `beeimg_cn` 自动获取可用存储，优先有效账号默认存储，否则取可用列表第一项；匿名仅查询 `group`。手填合法可用 ID 优先，非法或离表时刷新元数据后选择可用 ID；替代只作用于本次操作，不写回配置。查询失败或无可用存储转后续图床，不猜值；精确存储拒绝最多触发一次刷新重传。

### 期限入口与计算

- `expiration` 放在图床项顶层，与 `provider/token/options` 同级；只接受小写 `w/d/h/m/s` 的正整数降序组合，每单位最多一次，例如 `7d`、`1d12h`、`90m`；1 天固定为 24 小时。允许首尾空白和前导零，不接受内部空白、零值片段、负数、小数、大写单位、重复/逆序单位、空字符串或 `null`。
- 只有 `boltp`、`beeimg_cn` 将期限转换为上传参数；未配置时不发送期限，沿用站点策略。其他图床忽略合法期限并产生“该图床不支持保存期限，已忽略”告警；非法期限仍是配置错误，而非默默忽略。
- `expiration` 与 `options.expired_at` 同时填写为冲突。`options.expired_at` 不是绝对日期设置接口；实际发送值来自内部计算，不能靠手填选项覆盖。
- 从当前图片上传流程的起点计算绝对期限；组策略为正数时取更短值，并告警“保存期限已按图床上限缩短”。组策略为 0 不缩短，但 0 不代表永久保存。Boltp 期限信息仅通过 `group` 查询，不查询 `profile`。
- 同一图床项候选切换或受控重传沿用较早的历史期限，不重新开始计时；最终向下取整到秒，必须晚于当前时间且能由本机日期范围表示，否则该项失败。
- 两站发送本机本地时区的 `YYYY-MM-DD HH:MM:SS` 字符串；组策略仅是保守客户端缩短依据。服务端时区、策略优先级和实际删除时间均无保证，也不提供本地定时远程删图功能。

## Superbed 版本与双域上传

`provider: superbed` 缺省使用 `options.api_version: v1`。版本仅接受精确字符串 `v1` 或 `legacy`，不去空白、不转小写；不会自动跨版本或切换认证方式。

```yaml
provider: superbed
token: "${SUPERBED_API_KEY}"
```

新版使用 `X-API-Key`、multipart `files`、`/api/v1/upload/`，可选 `folder_id` 必须是 UUID 字符串；发送时保留原字符串。示例 UUID 仅说明格式，需要替换为账号实际文件夹 UUID，或省略该项。

```yaml
provider: superbed
token: "${SUPERBED_API_KEY}"
options:
  api_version: v1
  folder_id: "123e4567-e89b-12d3-a456-426614174000"
  permission: 1
```

兼容版使用表单 `token`、multipart `file`、`/upload`。可选 `categories` 是保留空白的层级路径字符串，也允许空字符串。

```yaml
provider: superbed
token: "${SUPERBED_API_KEY}"
options:
  api_version: legacy
  categories: "screenshots/2026"
  permission: 1
```

运行前由用户安全设置环境变量 `SUPERBED_API_KEY`，不要将凭证写入仓库。v1 中禁止出现 `categories`，legacy 中禁止出现 `folder_id`，即使值为空也拒绝。`permission` 只接受整数 1，`privacy` 不受支持；公开是项目约定，不表示已验证服务端权限。

原来省略版本的配置现在使用 v1。已有 `categories` 的配置必须显式增加 `api_version: legacy`，或主动迁移为真实文件夹 UUID；程序不自动转换路径或改写配置。

每次调用固定从 `api.superbed.cc` 开始，失败才尝试 `api.superbed.cn`，每域最多一个 POST，总计最多两个；任一成功即停止。两域失败后，按原配置顺序尝试后续图床；下次上传仍从 `.cc` 开始。每次请求连接/读取超时为 5/15 秒，启用 TLS 校验，不跟随上传重定向，不自动 HTTP 重试。超时不证明服务端没有保存图片，双域或后续图床重传可能产生重复文件；不承诺幂等、去重、两域同步或自动删除。

适配器只上传单个内存文件，不提供批量、远程 URL 抓取、Base64、目录或模板能力，也不下载图片验证。返回直链保留完整签名；更多接口资料、独立 HTTP 历史观测及其验证边界见 [Superbed API 参考](../Superbed_api.md)。
