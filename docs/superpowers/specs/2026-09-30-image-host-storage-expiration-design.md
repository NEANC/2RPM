# 图床自动存储、期限与安全诊断设计规格

- 日期：2026-09-30
- 复审日期：2026-10-01
- 状态：用户已确认设计及存储恢复修订；复审边界已明确，进入执行计划编写，尚未开始实现
- 范围：BeeIMG.cn、Boltp；SM.MS 不实现

## 1. 目标

为已接入的 BeeIMG.cn 与 Boltp 增加：

1. 自动获取账号可用 `storage_id`，优先账号默认存储；
2. 图床项顶层 `expiration` 时长配置，并转换为接口要求的 `expired_at`；
3. 业务拒绝与传输失败的安全分类；
4. CLI 调试模式下有限展示脱敏后的服务端业务提示；
5. 保持通知链路的安全输出、顺序故障转移与截图次数；仅增加本规格明确限定的存储刷新和最多一次上传重传。

不实现 SM.MS，不使用用户提供的真实令牌写入仓库、测试、缓存、日志或提交。

## 2. 已确认的官方接口证据

### 2.1 存储发现

两站均使用以下接口查询账号信息：

- `GET /api/v2/user/profile`
- `GET /api/v2/group`

账号默认存储字段来自 profile 的 `data.options.default_storage_id`；可用存储来自 group 的 `data.storages[]`，单项至少包含整数 `id`、名称和 provider。当前官方前端选择逻辑为：

1. 若默认存储存在且严格匹配 `data.storages[].id`，使用默认存储；
2. 默认字段缺失、为 `null` 或不在可用列表中，使用列表第一项；
3. 空列表没有可用存储。

上述接口和前端逻辑是官方证据。profile 字段的完整类型、服务端时区、以及 Bearer 是否在没有 Cookie/XSRF 时单独足够，仍未形成完整官方契约。实现不得读取浏览器 Cookie、自动登录或将认证失败伪装成“未设置默认存储”。

### 2.2 上传与期限

两站上传接口均为：

- `POST /api/v2/upload`
- `multipart/form-data`
- 必填 `file`、`storage_id`
- 可选 `expired_at`，格式 `yyyy-MM-dd HH:mm:ss`

BeeIMG.cn 的 group 文档将 `data.group.options.file_expire_seconds` 描述为文件失效时间（秒），`0` 为不限制。Boltp 的独立优先级语义尚未确认。两站均未明确无偏移时间字符串使用的服务端时区，也未明确组级失效策略与显式 `expired_at` 的优先级。

因此，`file_expire_seconds` 在本规格中是**保守客户端限制策略**，不是已确认的服务端最大期限契约；实现和文档不得声称保证实际删除时间。

## 3. 配置设计

图床项支持：

```yaml
image_host:
  - provider: beeimg_cn
    token: '${BEEIMG_CN_TOKEN}'
    expiration: 1d12h
    options:
      permission: 1
  - provider: boltp
    token: '${BOLTP_TOKEN}'
    expiration: 7d
    options:
      permission: 1
```

### 3.1 `storage_id`

- 已填写 `options.storage_id`：值为非布尔正整数且在可用列表中时，优先使用该手动值。
- 未填写：有令牌时查询 profile 与 group，优先使用在可用列表中的 `default_storage_id`，否则使用列表第一项；匿名时只查询 group，不请求需要登录的 profile，并使用可用列表第一项。
- 有令牌时元数据查询只向对应站点发送 Bearer，不读取浏览器 Cookie、不自动登录、不在认证失败后降为匿名。profile 的 data/options 必须是映射；有效 options 内默认字段缺失或为 null 表示未设置，非布尔正整数但不在列表中表示默认不可用，两者均选择列表第一项。其他默认值类型或取值视为元数据异常，不将数字字符串隐式转为整数。
- 手动值非法（包括布尔值、字符串、null、零或负数），或 ID 不在可用列表中：不使用该值上传，绕过旧缓存重新查询一次存储元数据。查询成功后，手动值若合法且重新出现在列表中则仍优先使用；否则按“账号默认存储优先，其次列表第一项”选择替代 ID，仅用于本次操作。
- 替代选择使用本次新查询结果；同一事件内已为同站点、同凭证完成该刷新时复用其结果，不因相同的无效配置逐图重复查询。每个图床项每张图片的刷新预算见第 4 节。
- 自动替代手动值时产生固定安全告警“指定存储无效，已自动选择可用存储”，事件内保序去重，不回显非法原始值、凭证或服务端原文。
- 查询失败、业务失败、JSON/结构异常、非法账号默认值或空列表：不猜测、不使用过期缓存，当前图床项失败并转下一图床。用户手填值非法与服务端元数据非法分开处理，后者不得触发盲目选取。
- 不修改用户配置及嵌套 options，不把替代 ID 写回配置。持久化缓存仅更新查询所得元数据，不把本次替代结果伪装成用户手动设置或账号默认值。

### 3.2 持久化缓存

- 缓存按站点和账号身份隔离；匿名身份单独隔离。
- 账号标识使用本机随机密钥计算的 HMAC 摘要；缓存不得保存令牌、Authorization、完整 profile/group 响应、完整 URL 或服务端原始错误。
- 保存必要元数据：格式版本、查询时间、默认存储 ID、可用存储 ID 与必要的组期限信息。
- 缓存位置使用应用本地缓存目录下的 `2RPM/image_host/`，不写入仓库或配置文件旁。
- 临时文件写入后原子替换；损坏、版本不兼容、时间异常或超过 24 小时均视为未命中。
- 同一次通知或 CLI 操作内复用查询结果和失败结果；多张截图不得仅因相同配置重复查询同一站点和账号。第 4 节规定的失效刷新是例外，刷新结果立即替换事件内旧元数据并供后续图片复用。
- 缓存写入失败不阻止本次使用已成功查询的元数据，但使用固定告警；无法可靠隔离身份时只使用事件内结果。
- 缓存到期刷新失败时，不使用旧缓存，当前图床项失败并转下一图床。
- 收到明确存储失效响应时，先使对应事件内和持久化记录失效，再查询；刷新失败不得让旧记录在下一事件重新命中。若失效记录无法可靠删除或覆盖，该进程禁用该身份的磁盘缓存并固定告警；缓存仅为性能优化，不作为授权或期限保证。
- 匿名只查询 group。有令牌时 profile 与 group 必须均成功并通过结构校验后，才将整份元数据作为一次成功查询保存；不拼接旧 profile 与新 group。成功响应中的存储 ID 必须为非布尔正整数，保留返回顺序，非法条目导致查询失败；不擅自跳过非法条目后选取其他存储。

### 3.3 `expiration`

- `expiration` 位于图床项顶层，不写入 `options`。
- 支持小写单位 `w/d/h/m/s` 的组合时长，单位从大到小、每种单位最多一次，数值为正整数。例如：`7d`、`1d12h`、`2h30m`。
- 拒绝空值、布尔值、负数、小数、重复单位、内部空格、未知单位和无法安全表示的过大时长。
- 未配置 `expiration`：不发送 `expired_at`，不产生期限告警，沿用站点策略。
- 配置了 `expiration` 但图床不支持期限：不发送该字段，固定告警“该图床不支持自定义期限，沿用站点策略”。本轮 BeeIMG.cn 与 Boltp 支持该字段。
- 每张图片第一次进入上传链时记录统一的绝对时间起点；1d 表示经过 24 小时，1w 表示经过 7×24 小时。各图床按照各自配置的 expiration 和组策略计算到期时刻，再转换为运行机器本地时区的日期字符串；备用图床共用起点，但不强制共用最终到期时刻。
- 同一图床重传沿用已计算的到期时刻，不重新起算。刷新后若组策略更短，只能进一步缩短；不得延长该图床本张图片已经确定的期限。
- 生成格式为 `yyyy-MM-dd HH:mm:ss`，不附时区偏移；实现必须明确这是运行机器本地时区，服务端解释可能不同。
- `file_expire_seconds > 0` 且请求期限更长时，按较短期限生成 `expired_at` 并产生固定告警；不声称这是服务端强制上限。
- `file_expire_seconds == 0` 不缩短期限，也不承诺永久保存。字段缺失或 null 表示上限未知，不擅自缩短；字段存在却为布尔、负数、非整数时视为元数据异常，不忽略错误继续上传。
- 单独提供 `options.expired_at` 而未配置顶层 expiration 时，保持原行为：不发送该原生选项，按不支持选项固定告警；本轮不增加第二种用户期限输入方式。
- 期限格式校验在获取存储元数据之前完成；合法 expiration 在不支持期限的图床上才按既定规则忽略并告警。仅去除首尾空白，明确拒绝整数、null 及空字符串；换算以绝对秒数相加再转本地时间，避免把跨夏令时的 1d 当作日历日。
- 期限已经过去时，该图床项请求前失败，不发送上传。
- `expiration` 与原生 `options.expired_at` 同时出现时视为冲突，固定参数错误，不静默覆盖。
- 期限告警在事件内保序去重，不携带凭证、URL 或服务端原文。

## 4. 上传与刷新流程

每张图片沿用现有图床列表顺序和首成功停止语义：

1. 解析并校验图床项；手填 `storage_id` 非法不立即终止该项，而进入第 3.1 节的重新查询与替代选择流程；其他参数错误仍按原规则处理。
2. 取得事件内元数据，优先使用有效缓存；需要纠正手填值时不得仅用旧缓存选择替代 ID。
3. 按第 3.1 节选择存储。手填值非法或不在列表中时，重新查询一次并选择可用 ID；查询失败或无可用 ID 则转下一图床，不发送上传。
4. 解析 `expiration` 并生成本图床的 `expired_at`，保留统一时间起点。
5. 使用选定 ID 发起上传；上传前修正无效 ID 后发送的是首次上传，不先发送一次明知无效的请求。
6. 成功则停止并返回完整 URL。
7. 已发送上传后，仅当服务端返回明确、站点绑定的存储失效业务拒绝，且本图床项本张图片尚未消耗刷新预算时，刷新一次存储元数据。按第 3.1 节重新选择：原手填值仍合法可用则优先保留，否则允许选用默认存储或列表第一项；刷新成功且选出可用 ID 后最多重传一次。
8. 刷新失败、再次失败、刷新预算已用尽或其他错误，转下一图床；不循环尝试所有存储。

上传后的自动刷新白名单在本轮明确为两条站点绑定规则：provider 为 beeimg_cn 或 boltp，HTTP 状态恰为 200，JSON 为映射，status 为字符串且精确等于 error，message 为字符串且精确等于“不存在的储存驱动”。全部条件同时满足才归为可刷新存储失效；不裁剪空白、不做模糊匹配，不因其他提示包含“存储/权限”而重传。

证据与授权边界：BeeIMG.cn 的该响应有历史真实请求样本；Boltp 尚无同类实测样本，由用户明确批准采用相同精确条件作为兼容策略，不声称已获官方契约或实测确认。两站均未取得该错误绝不会在服务端写入后发生的正式保证，因此不能承诺绝无重复图片；仅允许一次受限重传，不扩大到其他业务错误。

上传前发现手填值非法或不在列表中的处理不依赖此业务错误白名单。

以下情况禁止刷新重传：401/403、无效或过期令牌、423 或手机号/邮箱绑定要求、429/限流、内容审核、安全策略拒绝、普通 422 参数错误、网络中断、超时、5xx、JSON 解析或响应结构错误。

刷新和重传有严格上限：每个图床项每张图片最多一次纠错刷新、一次上传重传。上传前为无效手填值进行的刷新会消耗该预算；首次上传再遇存储失效时不进行第二次刷新，直接转下一图床。常规缓存未命中或到期后的首次查询不计为纠错刷新，但若其新结果已确认手填值不可用，直接据该结果选替代 ID，并视为已完成本次纠错刷新，不为相同问题重复查询。事件内复用该纠错刷新结果的后续图片同样不得为相同无效手填值重复刷新。

仅在本次操作内允许替代手填 ID；不重新截图，不改写用户配置、嵌套 options 或持久化的用户偏好。自动选择与重传均不得延长同一图床本张图片已经确定的请求期限；转入下一图床时按其自身 expiration 和组策略计算，但仍沿用本张图片统一的时间起点。

## 5. 错误分类与安全诊断

内部固定错误分类至少包括：

- `config_error`：配置、期限、存储选择冲突或结构错误；
- `storage_lookup_failed`：profile/group 查询失败或结构不可用；
- `storage_unavailable`：所选存储明确不存在或不可用；
- `transport_failed`：连接、超时、响应读取失败；
- `http_failed`：非 2xx；
- `business_rejected`：HTTP 成功但业务 status 表示拒绝；
- `invalid_response`：JSON、字段、状态或 URL 不符合契约。

通知和普通日志：

- 只输出固定中文摘要、错误码和阶段；
- 不输出服务端原文、响应全文、请求头、令牌、完整 URL 或配置；
- 不把诊断字段放入异常消息、`repr`、缓存或 `UploadResult` 的普通展示。

CLI `screenshot --upload`：

- 在固定安全摘要之外，可展示脱敏后的服务端 `message`；
- 仅提取长度受限的字符串 message；诊断开启时，过滤本次上传链配置中的令牌字面量、环境引用及成功解析的令牌，包括尚未尝试的备用站凭证。不输出预解析失败的异常，也不因此提前改变各站尝试顺序。
- 先进行脱敏与可疑内容判定，再截断至最多 200 字；清除控制字符和终端转义，过滤 URL、环境引用及凭证形态。超长原始 message 直接舍弃，不先截断原文再替换秘密，避免截出令牌片段。
- 诊断默认关闭，通知路径不收集业务 message；只有 CLI 显式启用收集。前站失败而备用站成功时，CLI 仍展示前站允许显示的安全诊断。
- 无法可靠脱敏时不展示原文，退回固定摘要；
- 不为获得诊断额外发送请求。

## 6. 测试验收

新增单元和集成测试必须使用合成 token、合成响应、本地 HTTP 替身或替换网络边界，不使用真实令牌、设备或外部上传。

必须覆盖：

1. 有令牌时 profile/group 成功、匿名仅查询 group、默认存储优先、默认字段缺失/null、合法默认不在列表、非法默认类型、列表第一项及空列表；认证查询失败不得降为匿名。
2. HTTP、业务、解析、鉴权、绑定、限流和内容审核错误的分类及不重传；两站精确白名单的正向用例，以及其他站点、非 200、非 error、近似提示、前后空白和非字符串字段均不触发重传的反向用例。Boltp 用例标注为用户批准的合成兼容测试，不冒称线上样本；
3. 24 小时缓存命中、过期、损坏、身份隔离、原子写入与写入失败；
4. 合法且可用的手动 `storage_id` 优先保留；手填值非法或不在列表时重新查询，按默认存储或列表第一项替代，配置及嵌套 options 保持不变；覆盖固定告警去重、刷新失败或空列表转下一图床、上传前不发送无效 ID、事件内复用纠错结果、上传前后共用一次刷新预算，以及明确业务拒绝后最多重传一次；
5. `expiration` 组合时长、非法值、统一起点、本地时区格式、上限缩短、告警去重、未配置时不发送字段；
6. CLI 脱敏诊断与通知固定安全输出；
7. 多目标、多通道和通知重试复用同一批次，不因查询或诊断重复截图或发送；上传次数仅允许第 4 节限定的存储失效重传增加，不因通道数或相同无效配置增加；
8. 输入配置、嵌套 options、环境变量和缓存之外的文件均不被修改。

真实 BeeIMG.cn 与 Boltp 上传、账号绑定、匿名访问及实际删除时间属于人工验证范围，不计入合成测试通过结论。

## 7. 明确不在本轮范围

- SM.MS；
- 新图床站点；
- 浏览器 Cookie、自动登录或账号绑定流程；
- 真实令牌持久化；
- 对服务端实际删除时间的保证；
- 通过猜测接口或字段补齐未确认契约；
- 与本功能无关的通知、监控、打包或 UI 重构。
