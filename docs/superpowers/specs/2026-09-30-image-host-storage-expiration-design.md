# 图床自动存储、期限与安全诊断设计规格

- 日期：2026-09-30
- 状态：设计已获用户批准，待用户审阅书面规格
- 范围：BeeIMG.cn、Boltp；SM.MS 不实现

## 1. 目标

为已接入的 BeeIMG.cn 与 Boltp 增加：

1. 自动获取账号可用 `storage_id`，优先账号默认存储；
2. 图床项顶层 `expiration` 时长配置，并转换为接口要求的 `expired_at`；
3. 业务拒绝与传输失败的安全分类；
4. CLI 调试模式下有限展示脱敏后的服务端业务提示；
5. 不改变通知链路的安全输出、顺序故障转移、截图次数和重试语义。

不实现 SM.MS，不使用用户提供的真实令牌写入仓库、测试、缓存、日志或提交。

## 2. 已确认的官方接口证据

### 2.1 存储发现

两站均使用以下接口查询账号信息：

- `GET /api/v2/user/profile`
- `GET /api/v2/group`

账号默认存储字段来自 profile 的 `data.options.default_storage_id`；可用存储来自 group 的 `data.storages[]`，单项至少包含整数 `id`、名称和 provider。当前官方前端选择逻辑为：

1. 若默认存储存在且严格匹配 `data.storages[].id`，使用默认存储；
2. 默认字段缺失、为 `null` 或不在可用列表中，使用列表第一项；
3. 空列表没有可用存储。

上述接口和前端逻辑是官方证据。profile 字段的完整类型、服务端时区、以及 Bearer 是否在没有 Cookie/XSRF 时单独足够，仍未形成完整官方契约。实现不得读取浏览器 Cookie、自动登录或将认证失败伪装成“未设置默认存储”。

### 2.2 上传与期限

两站上传接口均为：

- `POST /api/v2/upload`
- `multipart/form-data`
- 必填 `file`、`storage_id`
- 可选 `expired_at`，格式 `yyyy-MM-dd HH:mm:ss`

BeeIMG.cn 的 group 文档将 `data.group.options.file_expire_seconds` 描述为文件失效时间（秒），`0` 为不限制。Boltp 的独立优先级语义尚未确认。两站均未明确无偏移时间字符串使用的服务端时区，也未明确组级失效策略与显式 `expired_at` 的优先级。

因此，`file_expire_seconds` 在本规格中是**保守客户端限制策略**，不是已确认的服务端最大期限契约；实现和文档不得声称保证实际删除时间。

## 3. 配置设计

图床项支持：

```yaml
image_host:
  - provider: beeimg_cn
    token: '${BEEIMG_CN_TOKEN}'
    expiration: 1d12h
    options:
      permission: 1
  - provider: boltp
    token: '${BOLTP_TOKEN}'
    expiration: 7d
    options:
      permission: 1
```

### 3.1 `storage_id`

- 已填写 `options.storage_id`：保留手动覆盖；必须为非布尔正整数。
- 未填写：自动查询 profile 与 group，优先 `default_storage_id`，否则使用可用列表第一项。
- 手动值不在可用列表：视为存储失效，按刷新规则处理；不得静默替换为其他存储。
- 查询失败、业务失败、JSON/结构异常、非法默认值或空列表：不猜测、不使用过期缓存，当前图床项失败并转下一图床。
- 不修改用户配置，不把自动选择结果写回配置。

### 3.2 持久化缓存

- 缓存按站点和账号身份隔离；匿名身份单独隔离。
- 账号标识使用本机随机密钥计算的 HMAC 摘要；缓存不得保存令牌、Authorization、完整 profile/group 响应、完整 URL 或服务端原始错误。
- 保存必要元数据：格式版本、查询时间、默认存储 ID、可用存储 ID 与必要的组期限信息。
- 缓存位置使用应用本地缓存目录下的 `2RPM/image_host/`，不写入仓库或配置文件旁。
- 临时文件写入后原子替换；损坏、版本不兼容、时间异常或超过 24 小时均视为未命中。
- 同一次通知或 CLI 操作内复用查询结果；多张截图不得重复查询同一站点和账号。
- 缓存写入失败不阻止本次使用已成功查询的元数据，但使用固定告警；无法可靠隔离身份时只使用事件内结果。
- 缓存到期刷新失败时，不使用旧缓存，当前图床项失败并转下一图床。

### 3.3 `expiration`

- `expiration` 位于图床项顶层，不写入 `options`。
- 支持小写单位 `w/d/h/m/s` 的组合时长，单位从大到小、每种单位最多一次，数值为正整数。例如：`7d`、`1d12h`、`2h30m`。
- 拒绝空值、布尔值、负数、小数、重复单位、内部空格、未知单位和无法安全表示的过大时长。
- 未配置 `expiration`：不发送 `expired_at`，不产生期限告警，沿用站点策略。
- 配置了 `expiration` 但图床不支持期限：不发送该字段，固定告警“该图床不支持自定义期限，沿用站点策略”。本轮 BeeIMG.cn 与 Boltp 支持该字段。
- 以第一次进入上传链的本机本地时间为统一起点，备用图床及存储刷新重传沿用同一到期时刻。
- 生成格式为 `yyyy-MM-dd HH:mm:ss`，不附时区偏移；实现必须明确这是运行机器本地时区，服务端解释可能不同。
- `file_expire_seconds > 0` 且请求期限更长时，按较短期限生成 `expired_at` 并产生固定告警；不声称这是服务端强制上限。
- `file_expire_seconds == 0` 不缩短期限，也不承诺永久保存。
- 期限已经过去时，该图床项请求前失败，不发送上传。
- `expiration` 与原生 `options.expired_at` 同时出现时视为冲突，固定参数错误，不静默覆盖。
- 期限告警在事件内保序去重，不携带凭证、URL 或服务端原文。

## 4. 上传与刷新流程

每张图片沿用现有图床列表顺序和首成功停止语义：

1. 解析并校验图床项；
2. 取得事件内元数据，优先使用有效缓存；
3. 解析手动或自动 `storage_id`；
4. 解析 `expiration` 并生成统一 `expired_at`；
5. 发起一次上传；
6. 成功则停止并返回完整 URL；
7. 仅当服务端返回明确、站点绑定的“所选存储不存在/不可用”错误时，刷新该站点元数据并最多重传一次；
8. 刷新失败、再次失败或其他错误，转下一图床。

自动刷新白名单必须是结构化状态或站点绑定的精确业务条件。当前已知的历史文本“ 不存在的储存驱动 ”只能作为需进一步绑定站点的候选样本，不能用宽泛的“存储/权限”关键词触发重传。

以下情况禁止刷新重传：401/403、无效或过期令牌、423 或手机号/邮箱绑定要求、429/限流、内容审核、安全策略拒绝、普通 422 参数错误、网络中断、超时、5xx、JSON 解析或响应结构错误。

刷新和重传有严格上限：每个图床项每张图片最多一次刷新、一次重传，不循环、不重新截图、不改变用户手动指定的存储。

## 5. 错误分类与安全诊断

内部固定错误分类至少包括：

- `config_error`：配置、期限、存储选择冲突或结构错误；
- `storage_lookup_failed`：profile/group 查询失败或结构不可用；
- `storage_unavailable`：所选存储明确不存在或不可用；
- `transport_failed`：连接、超时、响应读取失败；
- `http_failed`：非 2xx；
- `business_rejected`：HTTP 成功但业务 status 表示拒绝；
- `invalid_response`：JSON、字段、状态或 URL 不符合契约。

通知和普通日志：

- 只输出固定中文摘要、错误码和阶段；
- 不输出服务端原文、响应全文、请求头、令牌、完整 URL 或配置；
- 不把诊断字段放入异常消息、`repr`、缓存或 `UploadResult` 的普通展示。

CLI `screenshot --upload`：

- 在固定安全摘要之外，可展示脱敏后的服务端 `message`；
- 仅提取字符串 message，先替换本次令牌，再移除控制字符和终端转义，过滤 URL/凭证形态，最多 200 字；
- 无法可靠脱敏时不展示原文，退回固定摘要；
- 不为获得诊断额外发送请求。

## 6. 测试验收

新增单元和集成测试必须使用合成 token、合成响应、本地 HTTP 替身或替换网络边界，不使用真实令牌、设备或外部上传。

必须覆盖：

1. profile/group 成功、默认存储优先、默认缺失/无效、列表第一项、空列表；
2. HTTP、业务、解析、鉴权、绑定、限流和内容审核错误的分类及不重传；
3. 24 小时缓存命中、过期、损坏、身份隔离、原子写入与写入失败；
4. 手动 `storage_id` 保留、失效刷新一次、刷新失败转下一图床；
5. `expiration` 组合时长、非法值、统一起点、本地时区格式、上限缩短、告警去重、未配置时不发送字段；
6. CLI 脱敏诊断与通知固定安全输出；
7. 多目标、多通道和重试复用同一批次，不因查询或诊断重复截图、上传或发送；
8. 输入配置、嵌套 options、环境变量和缓存之外的文件均不被修改。

真实 BeeIMG.cn 与 Boltp 上传、账号绑定、匿名访问及实际删除时间属于人工验证范围，不计入合成测试通过结论。

## 7. 明确不在本轮范围

- SM.MS；
- 新图床站点；
- 浏览器 Cookie、自动登录或账号绑定流程；
- 真实令牌持久化；
- 对服务端实际删除时间的保证；
- 通过猜测接口或字段补齐未确认契约；
- 与本功能无关的通知、监控、打包或 UI 重构。
